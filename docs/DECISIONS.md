# Decisions

Every deviation from the internal spec, one line each, newest last (spec §2, §19.2).

| Date | Decision | Why |
|---|---|---|
| 2026-10-17 | Planning docs (spec, demo script, architecture, task plans) live in `faber-eng/shared-context` under `projects/ai-builder-cup-bara/`, not in this public repo. Section numbers in this file and in scripts refer to `requirements-phase/REQUIREMENTS.md` there. | The code repo goes public (C4); plans stay internal. |
| 2026-10-17 | The pre-push hook runs `gitleaks git` instead of `gitleaks detect` (§19.5). | gitleaks 8.19 renamed `detect` to `git`; it is the same scan of the commit history. |
| 2026-10-17 | `.secrets/bara.env` holds only `PROJECT`. Model IDs come from `config/models.yaml` (C8). | One place for model IDs. |
| 2026-10-17 | `infra/setup.sh` creates what can exist before a deploy. Pub/Sub push subscriptions and the `run.invoker` grants for `bara-pubsub-invoker` and `bara-tasks-invoker` (§15 steps 3 and 4) wait for the `bara-api` event route (epic 01, BT-11). The `bara-jobs` deploy and the Cloud Scheduler jobs wait for epic 01, OT-1. | The subscriptions push to `POST /events/{topic}`, which does not exist yet, and `bara-jobs` is not deployed. |
| 2026-10-17 | `setup.sh` also enables `iam` and `cloudresourcemanager` (not in §15 step 1). | The IAM grants in step 3 call these APIs. |
| 2026-10-17 | `bara-jobs` gets `storage.objectAdmin` on the exports bucket only; `bara-api` on the evidence bucket only. | §15 gives no bucket for `bara-jobs`; the jobs write exports and never touch evidence. |
| 2026-10-17 | `scripts/preflight.sh` reads model IDs from `config/models.yaml`; `FAST_MODEL` and `REASONING_MODEL` override them (§15.1 put them in `.secrets/bara.env`). | One place for model IDs (C8). |
| 2026-10-17 | Preflight P2 passed on `ai-builder-cup-511906`: `gemini-3.5-flash` and `gemini-3.1-pro-preview` both return 200 on the `global` endpoint. No fallback needed. | §19.2: every external ID verified with a real call. |
| 2026-10-17 | `data/eval/labels.csv` has a header row with at least `object_path` and `licence`; `object_path` is relative to `gs://$PROJECT-bara-exports/eval/` (for example `photos/001.jpg`). | §15.1 names the fields but not the format; P4 needs one to check. |
| 2026-10-17 | **Cost rule:** the project runs on the Google Cloud free trial, USD 300 of credit. Every resource uses the free tier or the lowest tier. A budget `bara-free-trial-300usd` (5,370,000 IDR, the account currency, at about 17,900 IDR per USD) alerts at 25, 50, 75, 90 and 100%. | A spend overrun ends the trial and stops the demo. |
| 2026-10-17 | Cloud Run (`bara-api`, `bara-jobs`): min instances 0, max instances 3, request-based billing, 1 vCPU and the smallest memory that runs (start at 512 MiB; raise only if ffmpeg needs it). | Scales to zero between demos; free tier covers 2M requests a month. |
| 2026-10-17 | Gemini: during development and tests, `REASONING_MODEL` is set to the fast model, and unit tests never call a model. The Pro model runs only for the agent evals and the recorded demo. | Pro costs several times Flash per token; dev traffic does not need it. |
| 2026-10-17 | BigQuery: on-demand pricing, every query sets `maximum_bytes_billed`, tables are partitioned or clustered by week and cell. The re-ignition training table stays small (cells by events, not pixels). | 1 TB of queries a month is free; BigQuery ML training is billed per TB processed. |
| 2026-10-17 | Cloud Scheduler: 3 jobs, not 4 (§15 step 4). "Publish rankings" runs as the last step of the weekly drying job. | 3 Scheduler jobs per billing account are free. |
| 2026-10-17 | Cloud Build on the default machine type only; Artifact Registry keeps the last 3 images per service; the exports bucket deletes objects after 30 days, except `eval/`. | Free build minutes apply to the default machine; storage stays inside the free 0.5 GB. |
| 2026-10-17 | `apps/web/src/styles/kit.css` is a verbatim copy of shared-context `projects/ai-builder-cup-bara/requirements-phase/design/kit.css`. A change lands there first and is copied here the same day. | One source for the design tokens, so the app and the kit cannot drift. |
| 2026-10-17 | The contracts live at `services/api/contracts.py` (flat, §2), not `services/api/bara/contracts.py` as the Wave 0 TRD wrote. `apps/web/src/lib/contracts.ts` mirrors the shapes the web app reads. | §2 has no `bara/` package under `services/api/`. |
| 2026-10-17 | `tasks/{id}` adds `created_at` and `done_at` (null until done) to the §7 fields. | §9.1 `median_days_to_repair` needs task creation; `tasks_on_time_pct` needs the time a task was done. |
| 2026-10-17 | A §7 field marked `?` is stored as `null`, never omitted. `agent_runs.final_json` is the §6.2 output `{decision, reason, evidence, next_check_at}`, or `null` if the run failed. `bulletins.model` is `null` when `source` is `template`. | One shape for Python and TypeScript; a failed run is still stored for "why the agent did this". |
| 2026-10-17 | `bara-api` pins `google-genai==2.31.0`, `fastapi==0.143.3`, `uvicorn==0.54.0`, `pydantic==2.14.1`, `pyyaml==6.0.3` on Python 3.12 (§4.1); `uv.lock` is committed. `google-adk` is pinned when the agent lands. | §4.1 asks for pinned stable versions, recorded here. |
| 2026-10-17 | Gemini 5xx is retried by the SDK (3 attempts, 500/502/503/504). 404 and 429 are not retried: the gateway calls the fallback model once, and an error from the fallback propagates (§4.1, §14). | A 429 retried on the same model spends the wait the fallback avoids. |
| 2026-10-17 | The client is built with `enterprise=True`, the current name of the `vertexai=True` flag in `google-genai` 2.x (§4.1). | Same Vertex endpoint; `vertexai` is the legacy flag. |
| 2026-10-17 | `git_sha` reaches `/api/health` through the Docker build arg `GIT_SHA` (default `unknown`). `fallback_used` is per instance: true once any model call on that instance has fallen back. | No git in the image; Cloud Run instances do not share memory. |
| 2026-10-17 | CI/CD is a Cloud Build trigger `bara-main` on `main` (§3.1, §15.7), not a GitHub Action. `infra/trigger.sh` creates it; `cloudbuild.yaml` runs the API and web gates in parallel, then builds and deploys `bara-api`, then `firebase deploy --only hosting`, then checks `/api/health` through Hosting for the commit `git_sha`. | One platform for build and deploy; ADC replaces a long-lived Firebase token. |
| 2026-10-17 | The trigger runs as `bara-build`, not the default Cloud Build account (a trigger needs `--service-account` once the legacy account is gone). Roles: `logging.logWriter`, `firebasehosting.admin` and `serviceusage.serviceUsageConsumer` on the project; `artifactregistry.writer` on repo `bara`; `run.developer` on `bara-api`; `iam.serviceAccountUser` on `bara-api@`; `secretmanager.secretAccessor` on `maps-key` and `firebase-web-config` only. | Least privilege; no project-wide Editor and no secret access beyond the two the web build reads. |
| 2026-10-17 | The web build reads `VITE_MAPS_KEY` and the `VITE_FIREBASE_*` values from Secret Manager (`maps-key`, `firebase-web-config`) through `availableSecrets` and writes them to the gitignored `apps/web/.env.production` inside the build. The Firebase web config is public by design; it stays out of git so config lives in one place (C8). | The keys are never committed, and a rotated key needs no code change. |
| 2026-10-17 | `gcloud run deploy bara-api` in the pipeline sets only `--image`, `--region` and `--project`; scaling, memory, service account, env and the `invoker-iam-disabled` setting stay as `bara-api` has them. No private pool and no machine type override. | A deploy must not undo hand-set service config; default machine keeps free build minutes. |
| 2026-10-17 | Case edges are exactly the §7.1 table in `domain/case_machine.py` (14 edges). `reviewing -> assigned` and `assigned -> escalated` are illegal; `closed` has no exit. The test names every legal pair literally. | The diagram has no such edges; removing an edge must fail a test. |
| 2026-10-17 | The Google clients are the synchronous ones, and routes that use them are plain `def` (FastAPI runs them in a thread pool). Auth roles are `ops`, `volunteer`, `brigade`, `judge`; the claims `repair_team` and `patrol` authorize as `volunteer`. In judge mode (`config/app.yaml`, overridden by `BARA_JUDGE_MODE=0\|1`) a valid `X-Bara-Role` header wins over the claim and an unknown value is a 403; with judge mode off the header is never read. The ID token is always verified. `Principal.role_source` is `header` or `claim`, so ownership checks can apply to claim-based users only. | One client style across the adapters; a Firebase anonymous uid is real, so a judge still has a verified token. |
| 2026-10-17 | No CORS middleware. Firebase Hosting rewrites `/api/**` to Cloud Run, so the browser calls the same origin. (The evidence bucket CORS in `setup.sh` is separate: the browser PUTs to GCS.) | A permissive CORS setting would widen the API for no caller. |
| 2026-10-17 | `infra/setup.sh` grants `bara-api` `roles/iam.serviceAccountUser` on `bara-tasks-invoker`. | Cloud Tasks creates a task with an OIDC token for that account only if the caller may act as it (BT-14). |
| 2026-10-17 | `TaskRepository.due` queries `status == open` and compares `deadline_at` in code with `is_due`. | A Firestore equality plus inequality on two fields needs a composite index; the open set is small. |
| 2026-10-17 | Every BigQuery query goes through query parameters and sets `maximum_bytes_billed` (1 GB). `Warehouse.insert_rows` takes a table name checked against `[A-Za-z_][A-Za-z0-9_]*` inside the `bara` dataset. | SQL text never carries a value; cost rule above. |
| 2026-10-17 | `bara-api` pins `google-cloud-firestore==2.34.1`, `google-cloud-bigquery==3.46.2`, `google-cloud-storage==3.17.1`, `google-cloud-pubsub==2.43.0`, `google-cloud-tasks==2.26.0`, `firebase-admin==7.7.0`. `uv pip check` is clean next to `google-genai==2.31.0`. | §4.1 pinned versions. |
| 2026-10-17 | The deadline scheduler needs `BARA_API_URL` (the Cloud Run service URL, also the OIDC audience). When it is unset the API still boots with `scheduler = None` and logs a warning. | A new revision must pass the `/api/health` check before the URL is set; BT-14 needs it set. |
